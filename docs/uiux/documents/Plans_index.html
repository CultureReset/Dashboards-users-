01 · Big picture

The permanent Ghost architecture

The platform owns meaning and governance; everything that performs work underneath those contracts stays replaceable.

Ghost owns

Identity, tenancy, canonical business data, capability contracts, permissions, package registry, jobs, AppMaps, verification, evidence and receipts.

Open source supplies

Builder harnesses, workflow durability, browser/mobile runtimes, authorization/policy engines, secret management, repo intelligence and optional mesh/sandbox infrastructure.

The rule

Never let a vendor name become your architecture. Grok Build implements BuilderProvider; Playwright implements BrowserExecutor; ReDroid implements AndroidRuntime.

05 · Deployment

Local box, cloud node, or hybrid — same Ghost contract

The customer chooses where sessions and execution live. The UI stays the same because the capability router targets nodes, not hardcoded machines.

Local-first option

Keep Android sessions, browser profiles and selected files on customer-controlled hardware. The cloud control plane sends signed capability jobs to the node and receives status/evidence, not raw device credentials.

Cloud-only option

Each tenant receives persistent cloud execution resources. Cloud Android and browser sessions survive between tasks; the dashboard streams status and allows takeover without exposing raw ADB or worker credentials to the browser.

08 · Open-source & infrastructure placement

What to pull, exactly where it goes, and what stays replaceable

These tools are implementations behind Ghost interfaces. None should own your business model or become a mandatory product dependency.

Open source

Grok Build

Recommended first builder
Reference: x.ai/build + github.com/xai-org/grok-build
Ghost slot
BuilderProvider / HarnessProvider
What it does
Plans, explores, edits, tests and packages code; supports skills, plugins, hooks, MCP servers, subagents and headless/ACP operation.
How wired
Ghost Builder → GrokBuildAdapter → isolated build workspace → artifacts/tests → Ghost package validator.
Your options
Keep adapter boundary so Codex, an internal builder, or future coding agents can replace or coexist with it.
Open source reference

xAI Plugin Marketplace

Optional upstream catalog
Reference: github.com/xai-org/plugin-marketplace
Ghost slot
PackageSource (upstream)
What it does
Catalogs installable plugins that can bundle skills, agents, hooks, MCP and LSP components.
How wired
Marketplace importer → pin source/ref → inspect → security/license scan → map to Ghost capabilities → repack as Ghost package.
Your options
Never make xAI package format your internal format; import it through PackageSource.
Open source

Temporal

Recommended runtime
Reference: docs.temporal.io
Ghost slot
WorkflowEngine
What it does
Durable workflows that survive crashes, waits, retries and long-running business processes.
How wired
Ghost workflow definition → Temporal workflow → activities call capability router → waits/approvals resume from durable state.
Your options
For an MVP you can use a simpler Postgres job queue, then keep WorkflowEngine so Temporal can be adopted without changing product contracts.
Open source

Playwright

Primary browser executor
Reference: playwright.dev
Ghost slot
BrowserExecutor
What it does
Deterministic browser control with isolated or persistent browser contexts, DOM/ARIA selectors, storage state and multi-page support.
How wired
Capability router → browser provider → AppMap → Playwright worker → reread DOM/state → verification.
Your options
Use AI browser agents only for discovery/repair; compile successful paths back into deterministic Playwright/AppMaps.
Open source

ReDroid

Cloud Android option
Reference: github.com/remote-android/redroid-doc
Ghost slot
AndroidRuntime
What it does
Runs Android-in-cloud instances on Linux and supports persistent /data mounts; ADB must stay private.
How wired
Ghost node host → isolated ReDroid instance → private ADB → mobile executor/AppMap → stream/control gateway.
Your options
Also support physical Android via ADB; later add another cloud Android implementation behind the same AndroidRuntime interface.
Open source

Mobilerun / DroidRun

Useful mobile agent layer
Reference: github.com/appwiz/droidrun
Ghost slot
MobileExecutor + Mapping/Repair
What it does
Android/iOS agent framework using UI trees, screenshots, taps, swipes, typing and model-agnostic reasoning.
How wired
Unknown mobile state → Mobilerun discovery/vision → candidate semantic path → Ghost AppMap → deterministic executor next time.
Your options
Do not depend on its planner for known actions; keep direct Accessibility/UIAutomator/ADB path for deterministic runs.
Open source

Graphify

Recommended builder preflight
Reference: github.com/Graphify-Labs/graphify
Ghost slot
RepoKnowledgeProvider
What it does
Builds a queryable repo knowledge graph from code/docs/configs using deterministic AST parsing, and can expose it over MCP.
How wired
Repo URL/clone → GraphifyAdapter → graph.json → Composition Planner/Builder queries existing structure before changing code.
Your options
Optional for tiny repos; keep simple grep/AST fallback.
Open source

OpenFGA

Recommended fine-grained auth
Reference: openfga.dev
Ghost slot
AuthorizationProvider
What it does
Relationship-based authorization for users, organizations, businesses, devices, packages and resources.
How wired
Actor + object + relation → OpenFGA check → can this identity access this resource?
Your options
Keep application roles simple at first; use OpenFGA when multi-tenant/device/package relationships grow.
Open source

OPA

Recommended contextual policy
Reference: openpolicyagent.org
Ghost slot
PolicyProvider
What it does
Policy-as-code engine that separates policy decisions from enforcement.
How wired
Authorized actor + capability + risk + parameters → OPA → AUTO / ASK / NEVER + constraints.
Your options
Can start with a small internal policy module, then migrate policies behind PolicyProvider.
Open source

OpenBao

Recommended self-hosted secret store
Reference: openbao.org
Ghost slot
SecretStore
What it does
Identity-based secrets/encryption management for API tokens, passwords, certificates and dynamic credentials.
How wired
Connection record stores secret reference → worker requests scoped secret → OpenBao authenticates/authorizes → short-lived access.
Your options
Managed cloud secret managers can implement the same SecretStore contract.
Open source / experimental

Google SAM

Optional after core runtime works
Reference: github.com/google/sam
Ghost slot
MeshProvider
What it does
Zero-trust agent mesh with control plane, routers and local sam-node clients/MCP sidecars for remote tool discovery.
How wired
Ghost node daemon → SamAdapter → mesh identity/discovery → remote tool invocation.
Your options
Do not make SAM mandatory. Start with your own node gateway; NATS/WireGuard or another mesh can implement MeshProvider later.
Managed service SDK

Cloudflare Sandbox SDK

Managed build sandbox option
Reference: developers.cloudflare.com/sandbox
Ghost slot
SandboxProvider
What it does
Isolated stateful Linux code execution using Workers, Durable Objects and VM-isolated containers.
How wired

Your options
Local Docker/VM sandbox should remain available; use the managed service only when it fits cost/deployment requirements.

17 · Implementation order

Build one complete vertical slice, then widen it

Do not wire every open-source project on day one. Prove the permanent contracts with one capability across two executors.

Phase 0–1

Kernel

Contracts, DB IDs, tenancy, authorization, policy, secrets.

Phase 2–4

First capability

Temporal workflow + Playwright + verification + receipt.

Phase 5–6

Nodes & Android

Node daemon, cloud/local device, watch/takeover, same capability via mobile.

Phase 7–8

Builder

BuilderProvider + Grok Build + Graphify repo preflight.

Phase 9–10

Self-repair + packages

AppMap repair, regression, canary, marketplace lifecycle.

Phase 11–12

Scale options

SAM/mesh adapter, model routing, additional builders/executors.

First proof target

social.post.publish should run through one browser provider and one Android provider with the same capability request, permission policy, workflow and receipt. Then intentionally change a test UI and prove AppMap repair can detect, rebuild, test and promote a fix.
